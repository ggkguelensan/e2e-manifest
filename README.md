# E2E Manifest

Поведенческий E2E запускает настоящее приложение и проверяет законченный пользовательский результат. Тест управляет внешними зависимостями через HTTP runtime и адаптеры публичных интеграций. Существенные условия, действия и результаты видны в сценарии.

Для агента точка входа — [AGENTS.md](AGENTS.md). Режимы `dev`/`main`, установка Lefthook и выбор стековых модулей описаны в [installation.md](docs/installation.md).

## Начни здесь

По умолчанию работай локально: данные покрытия и индексы — CSV/JSON в игнорируемом `e2e/tmp/`; публикация и CI/CD требуют явного поручения. Полные границы — в [локальной политике](docs/local-workflow.md). Если проект содержит `e2e/manifest.json`, загрузи [проектные патчи](docs/project-patches.md) выбранной области.

Прочитай принципы и выбери документы по задаче в таблице ниже. При расширении задачи догружай правила затронутого слоя; весь комплект заранее читать не нужно. Документы нормативные, примеры интерфейсов иллюстративные. Команды, версии инструментов и настройки запуска берутся из целевого проекта.

## Принципы

1. **Один тест — один законченный пользовательский результат.** Полный основной путь каждой критичной роли находится первым; альтернативы и ошибки — в secondary suites.
2. **Gherkin ↔ spec сохраняет смысл.** Условия, порядок, значимые значения, действия, внешние события и результаты понятны без чтения реализации вспомогательных объектов.
3. **Существенное видно в spec.** Ожидания записываются явно, без вычисления результата по алгоритму приложения. Технические ожидания скрываются в UI-абстракциях.
4. **Journey необязателен.** Он объединяет повторяемый путь; POM владеет смысловой областью UI. Spec может использовать оба напрямую.
5. **Границы ответственности обязательны.** Behavioral spec не работает напрямую с DOM, HTTP, stores и внутренними callbacks. Fixture собирает зависимости, не выполняя скрытые существенные действия.
6. **Действия имеют владельца.** Пользовательская операция проходит через UI, серверное внешнее событие — через backend control, ответ провайдера — через external control.
7. **HTTP-поведение проверяемо.** Реальный browser и SSR используют общий MSW HTTP API. Мутации изменяют последующие ответы. Источники DTO и степень их подтверждения явны; типы и samples не выдаются за полный контракт.
8. **Состояние и время принадлежат сценарию.** Сценарии изолированы; завершение принятых запросов предшествует запуску следующего сценария.
9. **Ошибка остаётся видимой.** Нарушения контрактов и ошибки приложения проваливают тест. Сеть работает по явной политике, диагностика не раскрывает секреты.
10. **Готовность требует доказательств.** Смысловое ревью, запуск во всех настроенных профилях и необходимые проверки чувствительности дополняют друг друга. Скриншот дополняет assertions; visual baselines и committed PNG не используются.

## Ответственность

```text
spec → Journey → POM → Page
     → POM → Page
     → backend control → stubs → MSW HTTP runtime + DTO
     → native / external control → публичный bridge / SDK

Playwright fixture создаёт зависимости и управляет lifecycle.
```

Полная [диаграмма разрешённых зависимостей](stack/playwright/ui-abstractions.md#разрешённые-зависимости) определяет права слоёв. Прямой HTTP и lifecycle допустимы в инфраструктурных `runtime/*.spec.ts`, у которых отдельный предмет проверки.

## Граница доказательства

Synthetic E2E подтверждает поведение приложения при заданном серверном состоянии. Проверка DTO подтверждает соответствие используемым схемам, происхождение и ограничения которых фиксируются по [контрактным доказательствам](docs/contracts.md). Она не доказывает работу реального backend. Адаптер bridge/SDK не доказывает работу провайдера, а device profile — настоящего native WebView. `passthrough` smoke зависит от доступности и данных выбранного upstream.

## Готовность

Изменение готово, когда выполнены [проверки затронутых слоёв](docs/verification.md): сценарий переводится в Gherkin и обратно, нужные runtime/mutation-проверки пройдены, ограничения и проверенная ревизия указаны, временные probes и ненужные артефакты удалены.
