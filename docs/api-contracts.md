# API contracts

## Источник

Источник истины для HTTP-контрактов — опубликованная Swagger/OpenAPI-спецификация соответствующего сервиса.

Zod Mini-схемы synthetic E2E отражают опубликованный Swagger/OpenAPI-контракт, а не случайную форму существующего fixture или текущей frontend-реализации.

Перед созданием или изменением схемы сверяй актуальную операцию в Swagger: method, path, params, query, request body, response, required fields, optionality и nullable.

Если frontend расходится со Swagger, не ослабляй молча тестовую схему. Исправь frontend либо явно задокументируй подтверждённое исключение. Для отсутствующего в Swagger endpoint нельзя придумывать контракт.

## Структура

`api-contracts/` группируется по Swagger-сервисам. Отдельный файл представляет endpoint или тесно связанную пару request/response одной операции.

Именование фактически передаваемых shapes:

- `*BodyDTO`;
- `*ResponseDTO`;
- `*QueryDTO`;
- `*PathParamsDTO`.

Аббревиатура всегда пишется как `DTO`. Вложенная структура, реально используемая несколькими endpoint, называется `*Component` и размещается в `dto-components.ts`. Не называй компонент DTO, если сам по себе он не передаётся через HTTP.

DTO описывает полную ширину документированного shape. Не удаляй поля и не сужай тип только потому, что конкретному сценарию нужна меньшая часть ответа.

## Zod Mini

Пиши схемы непосредственно через `z.*`:

```ts
z.strictObject(...)
z.partial(z.strictObject(...))
z.optional(...)
z.array(...)
```

Не создавай обёртки, скрывающие стандартную семантику Zod, например `optionalStrictObject`. Различай отсутствующее поле, optional и nullable: они взаимозаменяемы только при таком контракте в Swagger.
