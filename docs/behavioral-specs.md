# Behavioral Playwright specs

## Интерфейс сценария

Один `test` представляет один законченный пользовательский результат. Arrange выбирает роль и серверное предусловие через custom fixture, после чего действия и наблюдаемые результаты идут в естественном хронологическом порядке.

Каждый вызов journey должен читаться как самостоятельный пункт инструкции человеку. Не сворачивай целый flow в один метод и не дроби его до технических кликов.

```ts
const user = await application.authorizedUser({ itemCount: 1 });

await user.openHome();
await user.openItems();
await user.findEligibleItem();
await user.startAction();
await user.setAmount(100);
await user.expectSummary({ feePercent: 10, total: 90 });
await user.completeAndExpectSuccess();
```

## Что остаётся в spec

- роль пользователя и существенные предусловия;
- действие пользователя;
- наблюдаемый результат;
- вводимые и видимые значения, важные для данного кейса;
- порядок обязательных шагов.

Записывай одноразовые значения непосредственно в вызове. Дублирование литералов в behavioral spec безопаснее лишних констант: ревьюер сразу видит вход и ожидание. Не вычисляй ожидаемую комиссию, итог, дату или статус внутри spec.

Постоянная продуктовая формулировка скрывается в POM. Передавай текст из spec только тогда, когда именно эта формулировка является переменным условием сценария.

## Чего в spec быть не должно

- `page`, locator, CSS, XPath и обход DOM;
- прямые `goto` на внутренний этап flow, если пользователь приходит туда через UI;
- API URL, request payload, route interception и ожидание конкретного запроса;
- IDs из fixtures;
- изменение stores или вызов внутренних callbacks приложения;
- `waitForTimeout`;
- assertions о количестве polling-запросов;
- условные ветки, воспроизводящие реализацию UI.

## Организация suite

- Основной файл начинается с полного простейшего happy path.
- Критичные роли пользователя получают отдельные полные happy paths.
- Короткий smoke допустим дополнительно, но не заменяет полный путь.
- Ограничения, предупреждения, ошибки и альтернативные состояния размещаются в secondary suite.
- Название теста описывает наблюдаемый результат в настоящем времени, без деталей реализации.
