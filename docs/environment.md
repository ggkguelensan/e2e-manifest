# Окружение и controls

**Когда читать:** подготовка данных, browser session, внешних событий или времени.
**Определяет:** сборку fixture, состояние stubs и публичные интерфейсы controls.

## Сборка окружения

Playwright fixture создаёт нужные POM, необязательные Journey и controls, подключает HTTP-операции и публичные внешние адаптеры, управляет очисткой. Существенные параметры подготовки выбирает spec. Автоматическая подготовка не выполняет проверяемые пользовательские действия.

Arrangement выражает предметное состояние: права пользователя, доступные билеты, комиссия, статус заказа. Не сужай допустимые типы до текущих кейсов: `number` не становится `1 | 2` только потому, что есть два теста. Synthetic IDs и transport payload остаются внутри окружения.

| Файл / интерфейс | Содержание |
| --- | --- |
| `*.fixture.ts` | Сборка зависимостей и lifecycle |
| `*.fixtures.ts` | Чистые данные запросов и ответов, без Page, handlers и изменяемого состояния |
| `*.stubs.ts` | HTTP-операции, минимальное состояние и предметные controls над ним |
| Backend control | Подготовка, внешнее событие, восстановление доступности |
| Native / external control | Наблюдение запроса и доставка ответа через публичный контракт |

## Серверное состояние

Подготовка устанавливает исходные условия. Во время сценария control воспроизводит внешнее событие, например отзыв предложения другим продавцом или восстановление сервиса. Название операции раскрывает событие, а не техническое присваивание статуса.

Проверяемая пользовательская операция проходит через UI и обычный HTTP-запрос приложения. Control не подменяет её прямым изменением synthetic state. Stubs применяют фактически принятые IDs и значения: последующие GET, reload и SSR отражают мутацию. Заранее зашитый успех независимо от request не подтверждает поведение.

Чтение возвращает состояние, не продвигая его по очереди ответов. Повторный GET сам по себе не завершает оплату, возврат или продажу. Условия перехода задаются явным внешним событием либо временем сценария.

## Внешние интеграции

Control устанавливает adapter публичного bridge/SDK, наблюдает запрос приложения и доставляет успех, ошибку, отмену или возврат. Он не меняет stores, не вызывает внутренние callbacks и не выполняет скрытые UI-действия.

Пример явно выраженной авторизации:

```ts
await home.open();
await nativeAuthorization.expectRequested();
await nativeAuthorization.complete();
await myTickets.expectAvailable();
```

Browser hooks и реализация публичного callback скрыты в control. Он проверяет необходимые условия протокола: нельзя завершить запрос, который не был сделан, или повторно завершить уже закрытую операцию. Несколько adapters должны сосуществовать, не перезаписывая чужие методы bridge; установку и очистку проверяют с учётом reload и порядка подключения.

## Время и polling

Даты строятся относительно единого scenario clock. Browser и synthetic server используют согласованное время. Для polling сервер сначала возвращает исходное состояние, затем меняет его относительно начала ожидания; повторные чтения до перехода стабильны. При управляемом истечении срока согласуй серверное время и часы браузера.

Behavioral E2E проверяет видимые состояния. Интервалы, количество запросов, отмена и остановка после terminal state проверяются unit-тестами модели. Проверки с произвольными будущими часами выявляют зависимость от фиксированной календарной даты.
