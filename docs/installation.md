# Установка и режим работы

Node и зависимости определены в `package.json` и lockfile. `npm ci` устанавливает зависимости без установки hooks, выбора стека и изменения checkout.

## Разработка базы

Используй подходящую development/task-ветку. Режим задаётся переменной на команду, а не именем ветки:

```sh
npm ci
E2E_MANIFEST_DEV=1 npm run setup
npm run hooks:install
```

Hooks устанавливаются явно только для checkout манифеста. При существующем `core.hooksPath` сначала проверь интеграцию; не обходи конфликт через force/reset. Переменная не записывается в глобальную конфигурацию. Для commit/push с установленными hooks передавай `E2E_MANIFEST_DEV=1`; разрешение публикации остаётся отдельным.

## Использование базы

Закрепи release/commit отдельно от приложения; consumer detached HEAD поддерживается:

```sh
npm ci
E2E_MANIFEST_STACKS=playwright,msw npm run setup
```

Без списка setup сохраняет пустой выбор и ничего не удаляет. Неизвестные ID, неверный режим и отсутствующие явно выбранные зависимости отклоняются до записи результата. Зависимости не подключаются молча.

`workdir/installation.json` — производная квитанция установки: mode, revision и modules. Это не адаптация target и не источник проектных предпочтений. Остальные файлы workdir сохраняются. Setup не выполняет fetch/switch, не меняет sparse checkout и не устанавливает skills в harness. Выбор здесь **не доказывает изоляцию контекста агента**; её обеспечивает отдельно проверенное нативное подключение выбранного target.

Не запускай установку параллельно с обновлением базы. Обновление ревизии и проверка совместимости адаптации — явные отдельные действия. Режим не зависит от main/dev, а квитанция не фиксирует mutable branch как версию базы.

## Проверки

Lefthook запускает только проверки: `pre-commit` — mode, `npm run check`, staged whitespace; `pre-push` — mode, check, test. Hooks не выполняют публикацию и не защищают remote сами по себе. При отсутствии hooks запускай проверки вручную; установка npm от hooks не зависит.

Каталог [stack](../stack/README.md) описывает доступные модули. Наличие файлов базы не означает, что все они доступны продуктовому агенту.
