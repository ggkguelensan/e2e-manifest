# Journeys и UI POM

## Journey

Journey композирует несколько UI POM и выражает путь или роль пользователя. Его публичный интерфейс использует язык намерений:

```ts
await user.findEligibleItem();
await user.startActionWithoutInterruption();
await user.expectCompletionSucceeded();
```

Journey может скрывать навигацию между несколькими страницами, перебор доступных пользователю объектов и различия mobile/desktop UI. Он не регистрирует routes, не импортирует DTO и fixtures и не знает synthetic IDs.

Инфраструктурную операцию, без которой нельзя воспроизвести внешний переход, передавай в journey через узкий callback. Journey вызывает намерение вроде `returnFromExternalVerification()`, но не знает, какой synthetic adapter реализует переход.

## UI POM

POM строится вокруг страницы, формы, диалога или семантической области, которая потенциально используется несколькими journeys. Он инкапсулирует локаторы, синхронизацию и адаптивные варианты разметки.

POM должен быть глубоким модулем: небольшой интерфейс скрывает заметную UI-механику. Метод, который только переименовывает один `locator.click()`, оправдан лишь когда сам локатор и его варианты действительно требуют локализации.

Не создавай POM под конкретный fixture, номер карточки или единственный scenario. Поиск подходящего объекта выполняется по наблюдаемым возможностям UI, а не по позиции или synthetic ID.

## Семантические локаторы

Приоритет обращения к DOM:

1. `getByRole` с accessible name;
2. `getByLabel`;
3. семантически ограниченная область и видимый текст;
4. стабильный пользовательский атрибут, если он действительно является частью интерфейса.

Не используй CSS-классы, XPath, цепочки дочерних элементов и `nth()` как идентичность объекта. Перед добавлением `data-testid` проверь, можно ли исправить роль, label или accessible name в приложении. Test ID не должен маскировать дефект доступности.

Диалог сначала ограничивается через `getByRole('dialog')`, после чего заголовки, тексты и действия ищутся внутри него. Одинаковые mobile/desktop намерения предоставляют один интерфейс POM, даже если реализация локаторов различается.

## Assertions

POM проверяет конкретное состояние своей области. Journey композирует эти проверки в пользовательский результат. Spec не повторяет locator assertions и не знает, какой DOM подтверждает шаг.

Не заменяй смысловые assertions скриншотами, снапшотами всей разметки или проверкой URL, если состояние можно подтвердить доступным заголовком, текстом или действием.
