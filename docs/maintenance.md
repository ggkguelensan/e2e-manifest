# Сопровождение манифеста

**Когда читать:** любое добавление или изменение правил, маршрутизации, skills, патчей и ресурсов. **Определяет:** обязательный смысловой SSOT-аудит и сокращение документации с сохранением progressive disclosure.

## Владелец смысла

| Содержание | Единственный источник |
| --- | --- |
| Общая норма | Документ соответствующей области; README даёт краткую ориентацию и ссылку |
| Проектное отличие | JSON-патч; подробности — зарегистрированный MD по [протоколу](project-patches.md) |
| Порядок работы агента | Skill, использующий нормы по ссылкам |
| Значения конфигурации, команды, версии, форматы данных | Исполняемая конфигурация или схема; документация объясняет использование, не создаёт вторую настройку |
| Факты, coverage, evidence и результаты | CSV/JSON в `e2e/tmp/` по [локальной политике](local-workflow.md) |

У одного смысла один нормативный владелец. Краткая ориентация допустима, если не вводит самостоятельных условий и ведёт к полному правилу. Проектное отличие не переписывает общую норму, а явно задаёт scope и разрешённый override.

## Обязательный SSOT-аудит

При каждом добавлении агент сначала ищет существующий смысл, затем меняет его источник и оптимизирует затронутую цепочку сопровождения. Проверяются не только совпадающие строки, но и перефразированные, частично пересекающиеся или противоречащие требования.

1. **Выдели смысл:** участник, действие/запрет, область, условия, исключения, последствия ошибки и способ проверки. Сравни эти части до и после правки.
2. **Найди владельца и потребителей:** README, docs, skills, project patches/MD, схемы, примеры и конфигурация. Начни со смысловых ключей и входящих ссылок; расширяй аудит по найденным связям, не перечитывая несвязанные проекты.
3. **Классифицируй пересечения:** точный дубль, перефразированный дубль, дополняющее условие, проектное отличие, противоречие или пример. Разные scope/предусловия не делают правила дублями автоматически.
4. **Оптимизируй SSOT:** обнови владельца, объедини совместимые условия, замени копии адресными ссылками, убери лишние посредники. Для значений используй конфигурацию/схему; необходимые физические копии генерируются из источника и не редактируются самостоятельно.
5. **Проверь сохранение смысла:** каждое прежнее действующее обязательство осталось у владельца либо изменено по явному требованию задачи. Противоречие не устраняется удалением неудобного ограничения; неясное решение требует уточнения до зависимой работы.
6. **Проверь стоимость чтения:** вход остаётся коротким, детали загружаются по задаче, обязательная норма не спрятана в optional reference. Меньше слов ценой длинной цепочки ссылок или большего числа обязательных файлов не считается улучшением.

После локальной оптимизации сделай обзор маршрутизации всего манифеста: нет ли осиротевших разделов, конкурирующих владельцев и сломанных потребителей. Несвязанный рефакторинг вне порученной области не выполняй; найденные проблемы обозначь отдельно.

## Progressive disclosure и сжатие

Три уровня: **README → правило выбранного слоя / применимый патч → условная деталь или процедура**. Ссылка объясняет, когда читать цель. Загружай ветку задачи, догружай при расширении scope, перечитывай уже известное только при изменении версии/содержимого.

Одна область ответственности — один документ. Разделяй по условиям чтения, а не ради количества файлов; короткий самодостаточный текст не дроби. Metadata, scope, время и read_when принадлежат JSON, подробности — MD. Обязательные ограничения находятся в основном правиле или rules-ресурсе; reference содержит только условные детали.

Сжимай смысл объединением эквивалентных формулировок, удалением повторов и заменой пересказов ссылками. Сохраняй условия, исключения, разрешения, ошибки и критерии готовности. Таблица объясняет выбор/ответственность, диаграмма — связи, полный пример — неоднозначное преобразование; соседний текст не повторяет их.

Не вводи универсальный лимит строк и не требуй отрицательного diff любой ценой: новое обязательство может увеличить текст. Рост обосновывается новым смыслом, а не повтором. Храни только актуальное нормативное состояние; историю хранит Git, результаты аудита — локальные рабочие данные.

## Изменение и проверка

Обновляй норму, schema/пример, маршрутизацию и потребителей одним изменением. При удалении/переносе проверяй входящие ссылки и target anchors; не оставляй alias-копии. При принятии проектного требования в базу удали дублирование из патча после проверки поведения. Общая база меняется только в задаче на её развитие.

Для затронутых патчей соблюдай [версию и время](project-patches.md#версия-и-время): ревью всех потребителей общего ресурса, revision и hashes; срок не продлевается вместо проверки. Публикация и CI/CD не следуют из локального аудита.

Перед завершением:

- Проверь ссылки, anchors, схемы, примеры и диаграммы; negative cases проверяют ограничения, включая фактический отказ неверной даты при включённом format checker.
- Проверь отдельно хронологию, hashes, scope и смысл конфликтов: JSON Schema не доказывает их корректность. Дата и порядок файлов не задают приоритет.
- Повтори затронутые маршруты чтения от README. Для spec, адаптации, контрактов и override должны быть понятны следующий шаг, условия остановки и результат без загрузки всего комплекта.
- Укажи область аудита, владельцев объединённых смыслов, удалённое дублирование, сохранённые ограничения и нерешённые конфликты. Различай парсерные проверки, ручное смысловое ревью и фактически выполненные workflows.

Краткий итог аудита входит в результат работы. Подробный индекс, если нужен, хранится в `e2e/tmp/` как CSV/JSON, не в нормативном документе. Не создавай постоянные тесты на точное совпадение формулировок.
