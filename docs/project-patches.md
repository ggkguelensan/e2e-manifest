# Проектные патчи и ресурсы

Читай при подключении базы, изменении проектных требований и обновлении версии. Общие нормы принадлежат базе; локальные дополнения находятся вне продуктового репозитория.

## Размещение

```text
<e2e-manifest>/
├── AGENTS.md
└── workdir/<project>/<target>/       # игнорируется Git, сохраняется при обновлении
    ├── manifest.json
    ├── patches/*.json
    └── resources/**/*.md
<product-worktree>/<target>/e2e/
├── AGENTS.md                        # короткая ссылка на адаптацию и закреплённую базу
├── CLAUDE.md -> AGENTS.md
├── README.md                        # команды
└── tmp/                             # аудит, coverage, evidence и отчёты
```

Формат адаптации — [schema](../schemas/project-manifest.schema.json), patches — [schema](../schemas/project-patch.schema.json), обе версии 2. Старые версии отклоняются без преобразования или удаления пользовательских данных. Repository/target IDs ссылаются на Project Manifest, если он подключён; при самостоятельной работе задаются явно. Адаптация не ведёт второй реестр путей/веток.

base.path относителен manifest.json; base.revision — точный Git commit. Фактическая база должна совпадать и быть чистой. Список modules задаёт выбранные возможности target, а не видимость skills в harness. Пути patches/resources относительны адаптации; scope — target root текущего worktree. Symlink и `..` не позволяют выйти за соответствующую границу. Scope обозначает существующий файл или поддерево, `.` — весь target.

## Применение и конфликты

```sh
npm run validate:adaptation -- --adaptation /absolute/e2e-manifest/workdir/project/web --base /absolute/e2e-manifest --target /absolute/worktree/apps/web --scope e2e
```

Команда проверяет JSON, format date-time, базу, IDs, пути, target anchor, выбранный stack, ресурсы и hashes. Вывод разделяет applicable active и pending proposed. Proposed не задаёт эффективных настроек; зависимая работа требует решения, независимая может продолжаться.

Для active: review.revision совпадает с revision и выполняется `updated_at <= reviewed_at <= now < review_due_at`. Изменение требований, scope, ресурсов или условий увеличивает revision, обновляет updated_at и возвращает proposed до фактического ревью. Срок не продлевается вместо проверки; mtime не заменяет даты. Смена базы требует повторного ревью даже до review_due_at.

Supplement добавляет предметные требования, не отменяя общие гарантии. Override разрешён только для типизированных settings по явно разрешённой точке расширения [предпочтений evidence](evidence.md#проектные-предпочтения). Он требует decision_ref. Несовместимые значения одной настройки в пересекающемся scope отклоняются независимо от порядка patches. Неизвестные settings запрещены.

Текст requirements и MD также проверяется на смысловые конфликты человеком или агентом: структурный валидатор не может доказать их отсутствие. При неразрешённом противоречии зависимая работа останавливается; дата, порядок списка и более узкий scope не создают автоматический приоритет. Workflow-требования применяются ко всем задачам своего scope; topic служит навигации.

Патчи не разрешают публикацию, CI/CD, real-backend действия, изменение продуктового runtime при адаптации, фиктивное покрытие или обход пользовательских ограничений. Они не меняют нативную иерархию инструкций. Свободный текст, противоречащий этим гарантиям, не применяется даже после структурной проверки.

## Ресурсы и progressive disclosure

Metadata, scope, даты и условия чтения принадлежат JSON. Краткие requirements не копируются в MD; resources нужны только для существенных подробностей. Каждый ресурс имеет ID, относительный path, summary, hash и kind:

- rules читается при применении патча; обязательные условия нельзя прятать за optional ссылкой;
- reference читается по read_when; он содержит условные подробности, примеры или процедуры.

Один MD может обслуживать несколько patches, но изменение его bytes требует обновления hashes и ревью всех потребителей. Незарегистрированный файл не становится правилом. Нормативные MD-зависимости также регистрируются как resources; их ссылки и смысл проверяются при ревью. Не загружай соседние каталоги автоматически.

Маршрут: AGENTS.md → target/задача → применимые patches → норма → выбранный stack → процедура → условный reference. Временный результат проверки сохраняется в e2e/tmp target; не переноси этот аудит в нормативные patches.

## Обновление и сопровождение

До обновления базы сохрани локальный workdir отдельно. Если подключён Project Manifest, его `npm run workdir -- export|restore` предоставляет копирование выбранного каталога с inventory/hashes и восстановлением только в новый каталог; процедура принадлежит его `docs/workdir.md`. Это необязательный инструмент: самостоятельная база допускает проверенную локальную копию средствами файловой системы. Checkout/setup не удаляет и не мигрирует его. После смены commit проверь применимость patches и hashes; несовместимость требует явного решения, а не автоматического принятия. Файл установки не является адаптацией target.

Каждое расширение проходит [SSOT-аудит](maintenance.md#обязательный-ssot-аудит): найди владельца смысла, убери дубли, сохрани условия и исключения, обнови схемы/потребителей. История остаётся в Git. Сжатие и маршрутизация определены в [maintenance](maintenance.md); публикация — в [локальной политике](local-workflow.md).
