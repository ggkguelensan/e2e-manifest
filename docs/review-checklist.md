# Чек-лист E2E-ревью

## Сценарий

- [ ] Один test описывает один законченный пользовательский результат.
- [ ] Первым идёт полный простейший happy path; критичные роли покрыты полными путями.
- [ ] Альтернативы, ограничения, ошибки и предупреждения отделены в secondary suite.
- [ ] Роль, существенные предусловия, вводимые и видимые значения понятны из spec.
- [ ] Ожидаемые суммы, даты и статусы записаны явно, без вычисления ожидаемого результата.
- [ ] Нет DOM/HTTP-механики, synthetic IDs, stores, внутренних callbacks и ветвления по реализации UI.
- [ ] Внутренний этап flow достигается через обязательные UI-шаги.

## Journey и POM

- [ ] Journey выражает намерения и не знает DTO, fixtures, routes и synthetic IDs.
- [ ] Внешний переход при необходимости передан через узкий callback.
- [ ] POM инкапсулирует переиспользуемую область и заметную UI-механику.
- [ ] Локаторы используют роли, accessible names, labels и семантическую область; test ID не скрывает дефект доступности.
- [ ] Нет зависимости от CSS, XPath, DOM-цепочек, позиции карточки и `nth()` как идентичности.
- [ ] Диалоги ограничены ролью `dialog`; mobile/desktop имеют общий интерфейс намерений.
- [ ] Assertions проверяют конкретное состояние; URL сравнивается точно или по значимой части.
- [ ] Нет `waitForTimeout`, snapshots всей разметки и подмены semantic assertions скриншотами.

## Контракты и backend

- [ ] Схемы сверены с опубликованным OpenAPI, включая полную ширину DTO и optional/nullable.
- [ ] `DTO` и переиспользуемые `Component` названы по ответственности; Zod Mini не скрыт за ненужными обёртками.
- [ ] Fixtures чистые; stubs владеют минимальным состоянием и учитывают принятый request.
- [ ] Arrangement выражает предметное состояние и не сужает типы до набора текущих кейсов.
- [ ] `strict`/`passthrough` и зависимости smoke явны; контрактная ошибка не включает upstream fallback.
- [ ] Настоящие SSR и browser используют один API; HTML и application API не подменены в браузере.
- [ ] Stateful response отражает действие, а не заранее зашитый успех.
- [ ] Единый scenario clock управляет датами; polling моделирует переход состояния.
- [ ] Mutable state/handlers изолированы; browser закрывается перед drain; следующий сценарий ждёт окончания предыдущего.
- [ ] Контрактные и hydration/application errors проваливают тест; журнал не раскрывает чувствительные данные.

## Проверка изменения

- [ ] Затронутые specs проходят во всех настроенных Playwright projects без подмены device profile.
- [ ] Typecheck приложения, lint затронутых файлов и `git diff --check` проходят.
- [ ] Unit-тесты покрывают связанные polling, таймеры, отмену и terminal state модели.
- [ ] Mutation audit делает тест красным при неверных IDs и существенных request/response-значениях.
- [ ] В `strict` неверные method/path и неизвестные API-запросы проваливают тест.
- [ ] В `passthrough` отдельно доказано отсутствие fallback при ошибке зарегистрированного контракта.
- [ ] Сценарии с датами проверены с произвольными будущими часами.
- [ ] Временные mutation specs и артефакты удалены.
- [ ] Изменённый runtime проверен прямыми HTTP/lifecycle-тестами с локальным upstream.
- [ ] Автономный CI и зависимый от upstream smoke разделены; отчёт и диагностика доступны при падении.

## Визуальные доказательства — если запрошены

- [ ] Формат результата определён; исходный behavioral scenario проходит.
- [ ] Каждый кадр сделан после semantic assertion и визуальной готовности, без devtools/debug overlays.
- [ ] Annotation не перекрывает UI и не меняет layout; кадр подтверждает видимое ожидание.
- [ ] Используются synthetic данные; PNG валидны и непусты, подписи и порядок сверены с manifest.
- [ ] Кадры временные `*.tmp.png`; нет `toHaveScreenshot`, baselines и committed PNG.
- [ ] Capture/reporting-код не добавлен в приложение, specs, journeys или POM.
- [ ] Один manifest используется для всех форматов; ссылки галереи проверены после загрузки и обновления.
- [ ] Изменение MR/PR поручено пользователем; остальные разделы и metadata сохранены.
- [ ] Standalone HTML проверен в браузере на desktop/mobile и не зависит от сети.
- [ ] Временные harness и кадры удалены после использования; нужные HTML assets сохранены вместе с отчётом.
