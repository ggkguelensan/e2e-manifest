# Проверка Playwright E2E

## Обязательный минимум

После изменения behavioral suite:

1. Запусти затронутые specs во всех настроенных Playwright projects.
2. Запусти typecheck приложения и lint затронутых файлов через штатные команды проекта.
3. Запусти unit-тесты моделей, если scenario зависит от polling, таймеров или terminal state.
4. Выполни `git diff --check`.
5. Убедись, что новые behavioral specs и journeys не содержат `data-testid`, CSS-селекторов, `waitForTimeout` и прямой регистрации routes.

Для контрактных стабов проведи mutation audit: неверные path/query/body IDs и существенные значения response должны делать тест красным. В strict неверный method/path и неизвестный `/api/**` запрос также должны проваливать тест. В passthrough незарегистрированные операции по определению идут в upstream; отдельно проверь, что ошибка зарегистрированного контракта не переключается на upstream. Временные mutation specs и артефакты удали после проверки.

Сценарии с датами дополнительно проверь с произвольными будущими часами сценария.

## Устройства

Mobile-first означает приоритет мобильного сценария, а не отказ от остальных configured projects. Не подменяй device profile вручную через user agent другого устройства. Различия адаптивной разметки скрываются внутри POM; пользовательский сценарий остаётся общим.

## Визуальные доказательства

Скриншот дополняет semantic assertion, но не заменяет его. В E2E не используются `toHaveScreenshot`, visual-regression baselines и committed PNG.

Если для ревью нужен кадр, создай локальный файл с суффиксом `*.tmp.png`. Он является временным доказательством, не участвует в assertions и не коммитится. После загрузки в MR или завершения проверки удали локальный файл.

Для каждой существенной визуальной проверки создаётся отдельный временный кадр с понятной подписью и отмеченной областью проверки.

Проверяй, что:

- annotation не перекрывает UI;
- изображение является корректным непустым PNG;
- ссылка на загруженный файл открывается;
- в кадре нет TanStack Devtools, debug overlays и служебных панелей;
- порядок кадров совпадает с порядком пользовательских шагов.

Правила создания MR/PR-галереи и standalone HTML: [визуальные доказательства](visual-evidence.md).
