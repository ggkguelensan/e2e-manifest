# Проверка изменений и диагностика

**Когда читать:** ревью, завершение изменения или разбор падения.
**Определяет:** необходимые доказательства и критерии готовности.

## Проверки по изменению

| Изменение | Обязательная проверка |
| --- | --- |
| Spec, POM, Journey, control | [Смысловой перевод](scenarios.md#проверка-перевода), затронутые сценарии во всех настроенных projects |
| Stubs или DTO | [Контрактный mutation audit](contracts.md#mutation-audit) и зависимые сценарии |
| Runtime, proxy, lifecycle | [Инфраструктурные тесты](http-runtime.md#инфраструктурные-проверки) с локальным upstream и затронутые suites |
| Polling, таймеры, terminal state | Unit-проверки модели на интервалы, отмену и завершение; E2E — на видимый результат |
| Даты и scenario clock | Запуск с произвольными будущими часами |
| Визуальное доказательство | [Capture и проверка выбранного формата](visual-evidence.md) |

Для изменений кода запускай штатные typecheck приложения и E2E, lint затронутой области и `git diff --check`. Mobile-first не исключает остальные настроенные проекты. Не подменяй device profile user agent другого устройства.

Смысловое ревью, runtime и чувствительность независимы: успешный запуск не подтверждает читаемость, а читаемый сценарий не гарантирует работающий assertion. Для изменённого поведения проверяй, что существенная ошибка делает тест красным; для контрактных стабов обязательна процедура mutation audit.

## Разбор падения

| Симптом | Источник доказательства | Следующий документ |
| --- | --- | --- |
| Неясно, что проверяется | Spec и перевод Given/When/Then | [Сценарии](scenarios.md) |
| Не найден элемент / неверное состояние | Trace, semantic assertion, фактический UI | [UI-абстракции](ui-abstractions.md) |
| Неверное серверное состояние / время / native-событие | Controls и состояние операции | [Окружение](environment.md) |
| Contract violation | Операция, схема, OpenAPI | [Контракты](contracts.md) |
| Неизвестный запрос / proxy / утечка состояния | `api-exchanges`, policy, lifecycle | [Runtime](http-runtime.md) |
| Ошибка приложения / гидратации | Browser/server diagnostics | Код приложения и [runtime](http-runtime.md) |

Не исправляй падение произвольным sleep, ослаблением схемы или увеличением retries. Сначала установи нарушенное ожидание и владельца ошибки. Сохраняй диагностику исходного падения; проверяй её перед публикацией на чувствительные данные.

## Критерии готовности

- [ ] Смысловой перевод выполнен без скрытых условий, действий и результатов.
- [ ] [Права слоёв](ui-abstractions.md#разрешённые-зависимости) соблюдены; публичные шаги соответствуют предмету сценария.
- [ ] Необходимые проверки из таблицы выполнены; различены новые и существующие падения.
- [ ] Подтверждена чувствительность затронутого поведения; для контрактов есть mutation audit.
- [ ] Проверенные revision, specs, profiles, policy и ограничения указаны вместе с результатом и ссылкой на report.
- [ ] Временные probes, намеренные поломки и ненужные артефакты удалены; нужные отчёты сохранены.

Отчёт о проверке принадлежит изменению или CI artifact, а не нормативному тексту манифеста. Не приравнивай наличие теста к прохождению, количество запусков на устройствах — к числу уникальных сценариев, а зелёный pipeline без E2E jobs — к браузерной проверке.
