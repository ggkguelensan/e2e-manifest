# Содержание отчёта

Читай для каждого формата. Отчёт — представление существующих результатов, не новый источник статуса теста.

Укажи target/repository, run и revision (включая локальные изменения), команду, profiles, время, область выполненных/не выполненных проверок и ограничения. При отсутствии данных пометь unknown/not-run: не выводи успех из наличия файла. Покажи retries и исходное падение. Считай сценарии и device executions отдельно.

Для каждого finding нужны стабильный ID, конкретный наблюдаемый результат, ожидаемое поведение, серьёзность с объяснением, источник и evidence refs. Рекомендация отделяется от установленного факта. Не создавай issues автоматически.

Для flow показывай последовательность действий и assertions. Для design comparison — исходный макет и фактический UI рядом, их ревизии, frame/node, spec/step и условия сравнения. Визуальные findings не меняют статус functional test. Непроверенные состояния и несопоставимые пары остаются в отчёте.

Порядок mobile/desktop следует согласованным предпочтениям; если они неизвестны, сохраняй фактический порядок и обозначь отсутствие предпочтения. Числовые viewport/browser берутся из выполненного запуска. Не объявляй симуляцию проверкой физического устройства.

Исходные изображения сохраняются. Crops/overlays/annotations ссылаются на оригинал и описывают преобразование. Pixel difference помогает локализовать расхождение, но не является автоматическим verdict. Не используй `toHaveScreenshot` или committed PNG baselines для этого отчёта.

Перед экспортом проверь персональные данные, секреты и разрешение распространения дизайн-ресурсов. Не изменяй Git ignore, не используй внешний хостинг без поручения. Доказательство, которое нельзя публиковать, остаётся локальным с явным ограничением отчёта.
